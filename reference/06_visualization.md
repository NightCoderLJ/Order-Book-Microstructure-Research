# Stage 6: Visualization and Pipeline Driver

## What problem does this stage solve?

Stages 1-5 each print numeric tables (throughput, label balance, IC,
ablation deltas, PnL/Sharpe) that a reviewer has to read carefully to
absorb. This stage adds two things, with no new modeling or analysis:

- **`viz.py`** turns eight of those already-established numbers/tables
  into plots, so the resume's claims ("tick-accurate", IC comparisons,
  the cost-blows-up-the-edge finding) are visible as pictures, not just
  printed digits.
- **`main.py`** runs every stage in the documented dependency order with
  one command, so the whole pipeline -- and every number/plot this
  project claims -- is reproducible from `config.yaml` and
  `data/raw/*.csv` alone.

Neither module computes a new metric Stages 1-5 didn't already define.

## Inputs and outputs

### `viz.py`

**Input**: `features.py`'s output table (`data/features/features.parquet`)
with `labels.py`'s `label_h{h}` columns added; `evaluate.py`'s baseline/
model IC tables; one XGBoost model fit via `model.py`'s own
`feature_columns()`/`normalize()`/`make_xgboost_model()` helpers (see "Why
one extra model fit" below); `backtest.py`'s `generate_oos_predictions()`
and `run_replay()`.

**Output**: 8 PNGs under `config.yaml: viz.output_dir`
(`reports/figures/`, gitignored, regenerated by running `python viz.py`):

| file | plot | source |
|---|---|---|
| `01_book_evolution.png` | best_bid/best_ask over the first `viz.book_evolution_events` events | `features.py`'s top-of-book columns |
| `02_spread_over_time.png` | instantaneous `spread` over the full day | `features.py` |
| `03_imbalance_distribution.png` | histogram of `queue_imbalance_w5` | `features.py` |
| `04_feature_importance.png` | XGBoost `.feature_importances_` (gain, normalized), one representative fit | see below |
| `05_predicted_vs_actual_return.png` | hexbin of out-of-sample score vs. realized forward return | `backtest.generate_oos_predictions()`, `labels.forward_return()` |
| `06_ic_by_horizon.png` | grouped bar chart, best baseline vs. both models, per horizon | `evaluate.evaluate_baselines()` / `evaluate_model()` |
| `07_pnl_curve.png` | cumulative PnL over trade sequence, signal replay vs. paper-trading | `backtest.run_replay()` |
| `08_drawdown_curve.png` | running drawdown over trade sequence, same two modes | `backtest.run_replay()` |

Every plotting function (`plot_book_evolution`, `plot_spread_over_time`,
etc.) takes already-computed data, not a file path or config -- this
keeps them pure and unit-testable on small synthetic tables
(`checks/test_viz.py`), independent of the real day's parquet file.
`viz.main()` is the one exception, exactly like every other stage's
`main()`: it reloads `features.parquet` from disk and recomputes what it
needs, so `python viz.py` is runnable standalone.

**Why one extra model fit for feature importance**: `model.py`
deliberately persists no fitted model object (see its docstring -- this is
a research comparison, not a deployed system), so `evaluate_model()` only
ever returns aggregate IC/accuracy/precision/recall/AUC, never a model to
call `.feature_importances_` on. `viz.fit_xgboost_for_importance()` fits
one XGBoost classifier on the *last* (largest) walk-forward fold's train
block, for `backtest.model` @ `backtest.horizon`, purely to visualize
which features it leaned on -- this is not a new evaluation claim; the
walk-forward IC comparison in
[reference/04_model_and_evaluation.md](04_model_and_evaluation.md) remains the
actual evaluation of model quality.

### `main.py`

**Input**: nothing beyond `config.yaml` (each stage's own `main()` reads
it directly).

**Output**: the full sequence of stage outputs, in `STAGES`' order --
`replay.main()`, `features.main()`, `labels.main()`, `evaluate.main()`,
`model.main()`, `backtest.main()`, `viz.main()` -- each called exactly as
it runs standalone, printing a header and wall-clock time per stage.
`python main.py` is a straight sequence, not a redesigned orchestrator:
each stage still reads its input from the file the previous stage wrote
(`features.py` -> `data/features/features.parquet` -> everything
downstream), exactly as documented in Stages 1-5.

## Assumptions and parameters (named in `config.yaml`)

| assumption | value | why |
|---|---|---|
| `viz.output_dir` | `reports/figures` | where plots are written (gitignored, regenerated by `python viz.py`) |
| `viz.book_evolution_events` | `8,000` | large enough to span both the day's ~1.3% genuinely uncrossed opening window and the point it becomes permanently crossed (reference/01), so the plot shows the transition, not just one regime |

## Why book evolution and spread look the way they do

`01_book_evolution.png` and `02_spread_over_time.png` are not smooth,
tight bid/ask lines -- they show `best_bid`/`best_ask` drifting apart and
`spread` trending increasingly negative over the day. This is the same
Level-10 depth-truncation finding documented in
[reference/01_ingestion_and_book.md](01_ingestion_and_book.md) and
[reference/05_replay_and_costs.md](05_replay_and_costs.md): once a stale,
never-cancelled order from outside the tracked top-10 depth becomes the
extreme best bid/ask on one side, it stays there, and the book never
becomes genuinely uncrossed again after the first ~1.3% of the day. The
plots are a faithful picture of the reconstruction, not a rendering bug.

## Sanity checks / invariants

- `checks/test_viz.py`: every plotting function is checked to write a
  non-empty, correctly-headered PNG (`\x89PNG\r\n\x1a\n` magic bytes) on a
  small synthetic table -- independent of `data/features/features.parquet`,
  so these tests pass even before that file has been generated.
  `fit_xgboost_for_importance()` is separately checked to return
  importances covering every column in `model.feature_columns()`.
- `checks/test_main.py`: `main.STAGES` is checked to cover every pipeline
  module's `main()` exactly once, and `main.main()` is checked (with every
  stage function replaced by a recording fake) to call all seven in the
  documented order -- without running the real multi-minute pipeline in a
  unit test.

## Reproducing

```bash
python viz.py    # requires data/features/features.parquet -- run python features.py first
                 # (~2 min: retrains xgboost on 5 folds for feature importance,
                 # oos predictions, and IC-by-horizon, then replays the full day twice)
python main.py   # the whole pipeline, one command, from data/raw/*.csv onward
                 # (~6-7 min measured end-to-end; dominated by model.py's ~180
                 # walk-forward refits, ~4 min, and viz.py's ~2 min)
```
